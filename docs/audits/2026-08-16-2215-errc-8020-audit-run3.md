## 6. Meta-Observation

Three runs in, the full-sweep-every-hour policy is producing diminishing returns, not proportional insight: run 3's finding set is roughly 90% a restatement of run 1/run 2 items with tighter numbers (30/54 branches, 14 workflows, 705 pyfunctions) rather than new discoveries, and the one piece of new information — the MCP planner regression — is exactly the kind of signal a diff-based approach would have caught cheaply and a full sweep buries in restated noise. The cost isn't just token spend; it's that "still open" items compound across runs with no visible action taken between them (branches, CI cache, workspace member), so the audit is documenting stasis rather than driving it. A diff-since-last-run mode would let each hourly cycle surface exactly what changed (regressions, new dead code, drift) instead of re-deriving the same 50-item backlog, and would make regressions like the MCP registration far more visible instead of one line in a 50-row table.
