KEY FINDINGS

1. PARSELOAD() IMPLEMENTATION (mcpp-route-conformance.test.ts:100-107)
   ────────────────────────────────────────────────────────────────

   function parsePayload(result: CliResult): Record<string, unknown> | null {
     try {
       const parsed = JSON.parse(result.stdout);
       return (parsed.payload as Record<string, unknown>) ?? parsed;
     } catch {
       return null;  // ← ONLY WAY TO GET NULL
     }
   }

   LOGIC: Returns null ONLY when JSON.parse(result.stdout) throws.

   This means: result.stdout is EMPTY or CONTAINS NON-JSON TEXT.

2. EXPECTED JSON ENVELOPE STRUCTURE
   ────────────────────────────────

   Top-level properties:
   - command: "trace conform"
   - status: "ok" | "error"
   - message: string
   - exit_code: number
   - payload: T                    ← parsePayload() extracts this
   - error?: { code, message, ... }
   - meta: { run_id, timestamp, duration_ms, version }

   ConformanceResult fields go into payload:
   - route_id, fitness, precision
   - required_stage_coverage, receipt_coverage
   - object_lifecycle_validity, observed_count
   - verdict, andon_reason, details, out

5. ROOT CAUSE OF FAILING TESTS
   ──────────────────────────

   JSON.parse(result.stdout) THROWS when:

   a) result.stdout === ''
      → JSON.parse('') throws SyntaxError
      → catch block returns null

   b) result.stdout contains non-JSON text (error, stack trace)
      → JSON.parse('Error: ...') throws SyntaxError
      → catch block returns null

   c) result.stdout is null/undefined
      → JSON.parse(null) throws TypeError
      → catch block returns null

   IMPLICATION: The conformance command is NOT outputting JSON to stdout.
