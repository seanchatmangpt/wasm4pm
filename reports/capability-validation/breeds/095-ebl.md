## 3. Actual Capability

Implements Explanation-Based Learning (EBL) via the EGGS algorithm for explanation-based generalization (Mitchell et al. 1986), as implemented in [ebl.rs](file:///Users/sac/wasm4pm/crates/wasm4pm-cognition/src/breeds/ebl.rs).

- **Inputs**: Expects:
  - `facts` defining properties of a specific training instance (e.g. `has_handle(obj1)`).
  - `rules` representing a domain theory (e.g. `cup(?y) -> drinkable(?y)`).
  - `goals` where the first goal specifies the training example to explain (e.g., predicate `drinkable(obj1)`).
- **Outputs**: Returns a `BreedOutput` where `selected` is the learned operational rule (e.g. `"has_handle(?y_g1), concave(?y_g1) => drinkable(?y_g1)"`). The `facts` array contains the original facts plus the new `ebl:rule` fact holding the rule. The `inference_trace` contains steps detailing SLD backward chaining proof steps (`ebl-explain`), EGGS generalized proof regression (`ebl-generalize`), and rule extraction (`ebl-operationalize`).
- **State Touched**: Stateless, runs in isolated linear memory.
- **Error Behavior**: Triggers error if facts/rules cannot prove the training goal.
- **Determinism**: Fully deterministic. SLD backward chaining searches rules sequentially, renaming variables with depth suffixes (e.g. `?y_1`) to avoid clashes, and unifying expressions using ordered `BTreeMap` structures, producing identical rules and output hashes.

## 4. Expected Semantics

- **Normal Case**: Proves a ground goal using SLD, regresses the proof tree from a generalized goal (`?target` replacing ground constants), unifies premises, and extracts leaf primitives as preconditions for a new operational rule.
- **Empty/Minimal Case**: Preconditions reject empty goals or missing rules.
- **Malformed Case**: Fails if the training goal cannot be proven (returns `EBL explain phase failed`).
- **Boundary Case**: Bounded at depth 32 in SLD backward chaining.
- **Non-Trivial Representative Case**:
  - **Mitchell 1986 Cup Example**: Given facts `has_handle(obj1)`, `concave(obj1)`, domain rules $R_1$: `cup(?x)` $\rightarrow$ `drinkable(?x)`, $R_2$: `has_handle(?y)` $\wedge$ `concave(?y)` $\rightarrow$ `cup(?y)`. Training goal `drinkable(obj1)`.
    - **Explain**: SLD backward chain: `drinkable(obj1)` $\leftarrow_{R1}$ `cup(obj1)` $\leftarrow_{R2}$ `has_handle(obj1)` $\wedge$ `concave(obj1)` (both are ground facts). Proof succeeds.
    - **Generalize**: Target is replaced with `?target`. Goal `drinkable(?target)` unifies with $R_1$ conclusion `drinkable(?x_g0)`. Premise is `cup(?x_g0)`. Unifies with $R_2$ conclusion `cup(?y_g1)` (mapping `?x_g0` to `?y_g1`). Premises are `has_handle(?y_g1)` and `concave(?y_g1)`, which match fact leaves.
    - **Operationalize**: Leaves are `has_handle(?y_g1)` and `concave(?y_g1)`. The head is `drinkable(?y_g1)`. The solver emits learned rule `has_handle(?y_g1), concave(?y_g1) => drinkable(?y_g1)` as `ebl:rule`.
  - **Applying Learned Rule (Hidden Oracle)**: The generated rule is added to a new domain theory. When presented with a new instance `obj99` having properties `has_handle(obj99)` and `concave(obj99)`, the SLD chainer matches and fires the learned rule in a single step to prove `drinkable(obj99)`.
