# Glossary

## Process Mining Concepts

**Activity** — A step or task recorded in an event log. In XES, the `concept:name` attribute.

**Alignment** — An optimal matching between a trace and a process model path. Computed by solving an A\* shortest-path problem over the product net.

**Breed** — One of the 9 Old AI symbolic systems in wasm4pm's cognition layer. Each breed accepts an `intent.json` contract.

**Case** — A process instance. One case = one sequence of events sharing the same `case:concept:name` in XES.

**Conformance Checking** — Measuring how well a discovered process model explains the event log. Primary metrics: fitness, precision.

**DFG (Directly-Follows Graph)** — A graph where nodes are activities and directed edges represent "A was directly followed by B in at least one trace." Edge weight = frequency.

**Event Log** — A collection of cases. XES format is XML-based; OCEL 2.0 is JSON/SQLite-based for object-centric logs.

**Fitness** — The fraction of the log that the model can replay without token deficits. Range: 0–1. wasm4pm's conformance gate requires > 0.85; MCPP route admission requires exactly 1.0.

**Generalization** — Whether the model captures behavior that was not in the training log. Measured via hold-out replay.

**Heuristic Miner** — A discovery algorithm that filters the DFG by a dependency threshold before constructing a model. More noise-tolerant than Alpha Miner.

**Inductive Miner** — A recursive discovery algorithm that guarantees a sound WF-net. The quality-tier default.

**OCEL 2.0** — Object-Centric Event Log format. Allows multiple objects per event across multiple object types.

**Petri Net** — A formal model with places (circles), transitions (rectangles), and directed arcs. Process models are typically WF-nets (Workflow nets).

**POWL** — Partially Ordered Workflow Language. A model type that explicitly encodes partial order among activities.

**Precision** — How much behavior the model allows that is not in the log. A model that allows everything has low precision.

**Process Discovery** — The task of inferring a process model from an event log.

**Simplicity** — Occam's razor applied to process models — fewer nodes and edges is better, all else equal.

**Trace** — The ordered sequence of events in one case.

**Token Replay** — Conformance checking by firing tokens through a Petri net. Fast but less precise than alignment.

**WF-net** — A Workflow net — a Petri net with a single source place and single sink place, satisfying soundness (every trace can complete).

**XES** — eXtensible Event Stream. XML-based event log format. Standard input for most process mining tools.

## wasm4pm Specifics

**BLAKE3 Receipt** — A cryptographic receipt emitted by every `wpm run` / `wpm cognition run`. Contains `input_hash`, `output_hash`, `run_id`, timestamp. Stored in `.wasm4pm/receipts/latest.json`.

**Handle** — An integer returned by `load_eventlog_from_xes()` or `load_ocel()`. Acts as a pointer into the WASM memory arena for a loaded event log.

**Kernel** — The WASM boundary layer (`@wasm4pm/kernel`). Wraps all 60 algorithm bindings and the WasmLoader singleton.

**Profile** — One of `fast`, `balanced`, `quality`, `stream`. Controls which algorithms the planner selects.

**Receipt** — See BLAKE3 Receipt.

**WasmLoader** — A singleton class in `@wasm4pm/kernel`. Call `WasmLoader.reset()` between tests.

**wpm** — The CLI binary (`@wasm4pm/cli`). Source of truth is `apps/wasm4pm/`. The Rust CLI at `crates/wasm4pm-cli/` is a dev tool, not published.
