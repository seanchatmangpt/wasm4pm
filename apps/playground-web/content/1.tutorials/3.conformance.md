# Conformance Checking

After discovering a model, **conformance checking** asks: *how well does the model explain the log?*

wasm4pm supports three conformance algorithms:

| Algorithm | Method | Speed |
|-----------|--------|-------|
| `token_replay_conformance` | Token-based replay | Fast |
| `alignment_conformance` | Alignment (optimal edit distance) | Quality |
| `footprint_conformance` | Footprint matrix comparison | Fast |

## Token Replay

Fires tokens through the Petri net for each trace. Counts missing and remaining tokens:

::AlgorithmDemo{algorithm="token_replay_conformance" preset="small-example" label="Token Replay Conformance"}

A `fitness` score of `1.0` means the model perfectly explains all traces. Values below `0.85` indicate significant deviation.

## Interpreting results

The result JSON includes:
- `fitness` — overall fitness score (0–1)
- `trace_fitness` — per-trace breakdown
- `missing_tokens` / `remaining_tokens` — where the model fails

A model with fitness < 0.85 should be re-discovered or the log re-filtered.

## MCPP route admission

wasm4pm's manufacturing pipeline requires **exactly 1.0 conformance** for MCPP route admission — no partial fitness allowed. This is stricter than academic standards.
