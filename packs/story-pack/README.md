# story-pack

Cross-product pack: every behavioral story x {Gherkin `.feature` file, QA
procedure doc, `docs/jira` ticket}.

## What it generates

`packs/story-pack/ontology.ttl` declares `compat:Story` and carries one
individual per authored story (one seed as of 2026-08-13:
`compat:StoryHelloWorldPrint`, transcribed verbatim from the user-supplied
`hello-world-print` feature/QA-procedure pair). Three `[[generation.rules]]`
entries in the root `ggen.toml` drive three templates off that same query
result set:

| Rule | Template | Output |
|---|---|---|
| `story-feature-files` | `feature.feature.tera` | `stories/{{ storyId }}.feature` |
| `story-qa-procedures` | `qa-procedure.md.tera` | `stories/{{ storyId }}-qa-procedure.md` |
| `story-tickets` | `ticket.md.tera` | `docs/jira/{{ storyId }}.md` |

## Authoring a new story

Add a `compat:Story` individual to `ontology.ttl`: `storyId`, `storyTitle`,
`scenarioName`, `givenStep`, `whenStep`, `thenStepTemplate` (containing the
literal `<output>` token), `qaScope`, and the multi-valued
`exampleOutputItem`/`qaPreconditionItem`/`qaProcedureStepItem`/
`passCriterionItem`/`failCriterionItem` properties — each value is its own
`[ compat:itemText "..." ; compat:itemOrder N ]` blank node, not a flat
value/order pair directly on the Story (a flat shape lets SPARQL's
shared-subject join cross-multiply every value against every order — found
and fixed live this session). Re-run `ggen sync run`; all three artifacts
are generated from the same facts, no hand-writing.

## Safety properties

- All three output paths are new/additive (`stories/`, `docs/jira/`) —
  nothing hand-written is at risk from a re-run.
- The ticket artifact is a Markdown file only — this pack never calls the
  GitHub API or opens a real issue; that remains a deliberate, separate,
  approved action if ever wanted.
- `mode = "Overwrite"` is correct because every output is a pure
  derivation of `ontology.ttl` — idempotent, never clobbers anything not
  itself generated by this pack.

## Query and template sourcing

`{ file = ... }` sourcing throughout, matching `workspace-pack` and
`paper-fidelity-docs`/`ci-workflows-render` — the only combination
confirmed to render on this ggen-engine version (`QuerySource::Pack` hits
`[FM-GEN-006]`).

## Files

- `pack.toml`, `qualification.toml` — pack metadata (mirrors
  `workspace-pack`'s shape).
- `ontology.ttl` — `compat:Story` class, properties, and the seed
  individual.
- `queries/extract-stories.rq` — one row per story; multi-valued fields are
  `GROUP_CONCAT`-joined via an `ORDER BY`-then-aggregate subselect per
  field, on the `"%%STORY_SEP%%"` separator token (never a bare `|`/`,` —
  real QA-procedure text legitimately contains both).
- `templates/feature.feature.tera` — Gherkin feature file.
- `templates/qa-procedure.md.tera` — QA procedure doc.
- `templates/ticket.md.tera` — `docs/jira/` ticket, Definition of Done
  built from the story's own Pass Criteria.
