# Institutional Review Board (IRB) Protocol & Ethical Guidelines
**Focus Area: Socio-Technical Deployment of Autonomous Process Systems (Layer L7)**

## 1. Overview and Purpose
This document outlines the standard operating procedures and ethical requirements for any doctoral research involving the deployment of `wasm4pm`, `Prolog8`, or `MCPP` systems into live community environments (e.g., local congregations, civic provision networks, gig-work coordination). 

Because the Vision 2030 framework addresses automation displacement and physical resource distribution, candidates are conducting research on vulnerable human populations. All Layer 7 deployments **must** pass IRB review before data collection begins.

## 2. Core Ethical Pillars
1.  **Beneficence and Non-Maleficence:** The deployment of edge nodes must strictly improve or maintain the local provision network's capacity. Any "fail-open" or "fail-closed" technical state must default to human override without penalizing the resource recipient.
2.  **Data Minimization & Anonymization:** Edge nodes operating on Object-Centric Event Logs (OCEL) must implement cryptographic anonymization at the point of ingestion. `Recipient` lifecycles must be decoupled from Personally Identifiable Information (PII) before the trace is admitted to the execution planner.
3.  **Explainability (HITL):** If a state transition is denied by the `Prolog8` bounded logic engine (e.g., a resource request is rejected), the counterfactual justification generated by s(CASP) must be tested for layperson comprehensibility.

## 3. IRB Proposal Requirements
Before initiating a Field Lab (e.g., Lab 400 - Edge Deployment in a Civic Context), candidates must submit a protocol containing:
*   **The Social Fallback Matrix:** A flowchart detailing the manual, paper-based fallback procedures if the local edge node, network, or MCPP actor-supervision tree fails catastrophically.
*   **Participant Consent Forms:** Plain-language consent agreements for the network operators (e.g., congregational volunteers) explaining that their workflow routing is governed by compiled WASM logic.
*   **Cryptographic Audit Strategy:** A demonstration of how the BLAKE3 receipt chain will be used by local auditors without exposing the underlying PII of the resource recipients.

## 4. Example Scenario: The Gig-Worker Resource Allocation
*If a candidate is testing how POWL constraints handle concurrent volunteer dispatches in a local food bank:*
The IRB must review the risk of "algorithmic starvation"—what happens if the `stream` profile incorrectly drops a legitimate object lifecycle due to cardinality exhaustion? The candidate must prove that their `proof-gate` implementation emits an alert to a human supervisor immediately upon an anomalous lifecycle drop, guaranteeing zero harm to the service population.
