# Upload Your Event Log

The playground accepts event logs in two industry-standard formats: XES (XML-based) for classical process mining and OCEL 2.0 JSON for object-centric analysis. This guide walks through every way to get your data in.

## Accepted Formats

| Format | Extension | Standard | Best For |
|--------|-----------|----------|----------|
| XES | `.xes` | IEEE 1849-2023 | Classical single-case-notion logs |
| OCEL 2.0 JSON | `.json` | Object-centric | Multi-object, many-to-many event logs |

Both formats are parsed entirely in your browser via the WASM core — your data never leaves your machine.

## Three Ways to Load Data

### 1. Paste Directly

Click the **Paste** tab in the log panel, then paste raw XES XML or OCEL JSON into the text area. Hit **Load** when ready. This is the fastest path for small logs or for sharing a snippet in a bug report.

### 2. Drag-and-Drop a File

Drag a `.xes` or `.json` file from your file manager and drop it anywhere on the log panel. The panel border highlights in blue when a valid drop target is active. The file is read client-side via the File API — no upload to any server occurs.

### 3. Use a Preset

Presets are bundled example logs shipped with the playground. Click the **Presets** dropdown to choose from:

- **small-example** — A compact synthetic log with 5 cases and 3 activities. Good for algorithm exploration.
- **purchasing** — A real-world purchase-to-pay log (anonymised).
- **ocel-example** — An OCEL 2.0 JSON log with `Order`, `Item`, and `Route` object types.

## After Loading

Once a log is loaded, the header bar shows:

- **Cases** — number of distinct case IDs (XES) or object IDs (OCEL)
- **Events** — total event count
- **Activities** — unique activity labels
- **Format** — detected format badge (XES / OCEL 2.0)

All algorithm panels will refresh automatically when you load a new log.

## Troubleshooting

### File Too Large

The WASM streaming parser holds the full log in memory. Practical limits:

| Format | Soft Limit | Hard Limit |
|--------|-----------|------------|
| XES | 50 MB | 200 MB (browser-dependent) |
| OCEL 2.0 JSON | 25 MB | 100 MB |

If your log exceeds the soft limit, a warning banner appears. The algorithm will still attempt to run but may be slow. To reduce size: filter to a time window, sample cases, or remove non-essential attributes before loading.

### Wrong Format Detected

The parser uses file extension first, then content sniffing. If your XES file has a `.xml` extension, rename it to `.xes`. If your OCEL JSON was exported from pm4py with a non-standard wrapper, flatten it so the top-level keys are `"ocel:events"` and `"ocel:objects"`.

### Encoding Issues

XES files must be UTF-8. If your log was exported from a legacy tool with ISO-8859-1 encoding, convert it first:

```bash
iconv -f ISO-8859-1 -t UTF-8 my-log.xes -o my-log-utf8.xes
```

OCEL JSON must be valid UTF-8 JSON. Run `python3 -m json.tool my-log.json > /dev/null` to validate locally before loading.

### Attribute Values Show as `[object Object]`

This happens when an XES attribute of type `list` or `container` is present. The playground renders scalar attributes (string, date, int, float, boolean) only. Nested attributes are ignored. This is expected behaviour and does not affect algorithm results.
