# Pattern sequences

A pattern language becomes operational through sequences. The following sequences are reusable for wasm4pm design and review.

## Sequence A: Admit a new effectful capability

1. **Mindmap** the vocabulary and stakeholder concepts.
2. **Requirement** the invariants, risks, and verification methods.
3. **C4 Context and Container** identify trust and execution boundaries.
4. **Class and ER** define typed carriers and persistent evidence.
5. **Flowchart and Sequence** define the lawful path and refusal branches.
6. **Packet** fixes canonical receipt serialization.
7. **State** defines standing promotion and regression.
8. **Gantt and Kanban** coordinate implementation and evidence gates.
9. **Ishikawa** diagnoses failed proof ladders.
10. **GitGraph and Timeline** record admission history.

## Sequence B: Review an existing architecture

Begin with C4 Context, Container, and Component. Trace one critical path using C4 Dynamic and Sequence. Verify type ownership using Class and cardinality using ER. Use Requirement to connect invariants to evidence. Finish with State to assign honest standing.

## Sequence C: Explore an open design space

Begin with Mindmap and Cynefin. Keep Complex work in CONSTRUCT and use Quadrant to distinguish standing from reversibility. Use Wardley to avoid custom-building commodity dependencies. Convert selected candidates into Requirements before they approach BRCE.

## Sequence D: Diagnose a broken release

Use State to classify the failure, Ishikawa to enumerate hypotheses, XY to inspect measured regressions, Packet to inspect carrier ambiguity, Sequence to compare observed order with intended order, and GitGraph to locate the first divergent commit.
