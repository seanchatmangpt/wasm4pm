# Preface

Design for Combinatorial Maximalism, abbreviated **DCM**, is a method for creating large design spaces without surrendering control of effects. The apparent paradox is deliberate. A system should be maximally generative in the graph domain and maximally conservative at the machine-state boundary. It may construct many candidates, combine many ontologies, derive many plans, and project many artifacts. It may actuate only through a bounded authority path, and every actuation must leave evidence that can be independently replayed or verified.

This book turns Mermaid itself into a pattern language. A flowchart, class diagram, Wardley map, packet diagram, and mindmap are not interchangeable decorations. Each answers a different question. Combinatorial maximalism arises when these views remain orthogonal and can therefore be composed without collapsing their meanings.

The case study is `wasm4pm`: a proof-carrying process-manufacturing architecture built around bounded observation, reversible construction, authority brokerage, receipts, replay, public ontologies, Rust/WASM execution, and typed standing. Some diagrams describe current source-grounded structures. Others describe target composition roots, diagnostic hypotheses, or planning views. Every chapter labels that distinction.

The intended reader is an architect, researcher, verifier, or agent designer who needs more than an attractive architecture deck. The patterns are written to be falsifiable. A reader should be able to inspect source, run a proof ladder, and either uphold or reject each depicted relationship.
