## 3. Actual Capability

Discovers a Petri net model from an event log using an Integer Linear Programming (ILP) formulation (`discover_ilp_petri_net` in `ilp_discovery.rs`). It solves a greedy set-cover problem over candidate places.
- **Actual inputs**: `eventlog_handle` (string handle), `activity_key` (string attribute name).
- **Actual outputs**: A JSON string representing a PetriNet with its `handle`, `places` count, `transitions` count, and `arcs` count.
- **Actual state touched**: WASM global thread-local storage (`StoredObject::EventLog` read, `StoredObject::PetriNet` written).
- **Actual error behavior**: Returns an empty PetriNet if the log is empty or if no activities are present.
- **Determinism/replay behavior**: Fully deterministic. Sorting the causal pairs deterministically ensures that candidate generation and greedy cover selection are stable.

## 4. Expected Semantics

- **Normal case**: Extracts causal, parallel, and length-1 loop activities. Generates candidate places (1-to-1 causal pairs, AND-splits, and AND-joins). Validates candidates using token replay (retains places that are consistent and useful). Applies greedy set-cover to select the minimal set of places covering all causal pairs, then builds the Petri Net.
- **Empty/minimal case**: Returns an empty PetriNet.
- **Malformed case**: Skips invalid traces.
- **Boundary case**: Single trace with a few events results in a linear chain of places and transitions.
- **Non-trivial representative case**: Log with parallel branches (e.g. `a->b->d` and `a->c->d`), where AND-splits and AND-joins are successfully generated and selected.
