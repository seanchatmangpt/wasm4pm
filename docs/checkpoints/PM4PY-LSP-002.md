However, release-level validation is incomplete due to missing behavior receipts and release certificates, presenting a gap in the receipt taxonomy.`

---

## 1. Surfaces Classification

### A. Admitted Surfaces
- **Deterministic Hashing**: The `SnapshotId` is generated by sorting active document URIs and hashing them along with their contents using the BLAKE3 algorithm.
- **Artifact Persistence**: Generated fixtures and verification receipts are persisted directly to physical directories (`fixtures/pm4py-parity/` and `receipts/pm4py-lsp/`).
- **LSP Lifecycle**: Document states are fully synchronized in memory on `didOpen` and `didChange` events, and cleaned up on `didClose`.
- **Quickfix Code Actions**: The server identifies unformatted dataframes and recommends automatic insertions of formatting methods.
- **Actuation Commands**: Execution of `pm4py-lsp.formatDataFrame` and `pm4py-lsp.createParityFixture` automatically modifies document files, calculates hashes, and outputs receipts.
- **Conformance Vector Shifts**: System state shifts dynamically from refused to admitted when the formatting repair is applied.
- **Optional Runtime Bridge**: Incorporates Pyo3 GIL execution with a default Static fallback mode for safe environment execution.
- **Parity Fixture Contract**: Supports equivalent outcome validations using equivalence metrics (`EquivalenceKind`) and gap classifications.
- **Comprehensive Capability Coverage**: The server parses, flags, and executes the full range of PM4Py process mining capabilities, including Discovery (DFG, Alpha, Inductive, Heuristics Net, Process Tree, DECLARE), Conformance Checking (Token-based replay, Alignments, WF-net soundness), and Exports (XES, BPMN, Petri net, Process Tree).
- **Alternative Load Detection**: Static analysis detects diverse event log ingestion formats (CSV, Parquet, JSON, Excel) and pandas load functions, guarding execution across all inputs.
- **Dynamic Bridge Execution**: The PyO3 bridge automatically discovers dependencies (e.g., extracting Petri nets dynamically to run token-based replay, or generating process models to run file exports).

### B. Refused Surfaces
- **Unformatted DataFrames**: Standard process mining workflows that attempt to execute process discovery on raw, unformatted pandas DataFrames are flagged with warnings and refused admission.
- **Missing Log Columns**: Workflows containing formatting commands that omit event log mapping inputs (`case_id`, `activity`, `timestamp`) are flagged as invalid.
- **Invalid Actuation Commands**: Actuation requests passing malformed arguments or references are refused by the JSON-RPC interface.
- **Corrupted Verification Receipts**: Modification of persisted receipt files or hashes triggers verification failures.

### C. Unknown / Future Surfaces
- **Automatic Replay Execution**: Compiling and replaying the parity fixtures directly on the `wasm4pm` WASM engine (currently simulated at the interface contract layer).
- **Extended Formats**: Non-CSV event log parses (e.g. XES, OCEL datasets).
- **Process Optimization**: Formally mapping fitness/precision statistics to compiler optimization profiles.
