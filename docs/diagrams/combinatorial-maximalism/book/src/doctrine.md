# DCM doctrine

## The Chatman equation

The compact formulation is:

\[
A = \mu(O^*)
\]

`O*` is admitted, bounded observation. `μ` is lawful manufacturing. `A` is an artifact with standing. The equation refuses two common shortcuts. Raw observation does not directly become an artifact, and manufacturing is not merely generation. It is generation constrained by admission, authority, evidence, and replay.

## SELECT and DO become CONSTRUCT and ACTUATE

Traditional agent systems often alternate between selecting a tool and executing it. DCM separates a far larger reversible domain from a narrowly controlled irreversible domain:

- **CONSTRUCT** explores graph-domain candidates, joins public ontologies, expands process models, derives proof terms, and prepares projections.
- **ACTUATE** changes machine state. It writes, runs, deploys, publishes, sends, or mutates.

The broker is the only lawful path from CONSTRUCT to ACTUATE.

## BRCE

The Brokered Receipt-Carrying Execution invariant is:

> Zero unreceipted actuation.

A broker decision must be scoped to the session, capability, subject, policy, and bounded request. The result must produce a receipt that binds the decision and effect. Broad ambient grants are not sufficient.

## Standing

DCM uses typed standing instead of narrative completion:

- `UNKNOWN`
- `PARTIAL_ALIVE`
- `ALIVE`
- `BUILD_BROKEN`
- `BLOCKED`
- `UNSUPPORTED`

Promotion to `ALIVE` requires the relevant proof ladder. A source file can be ALIVE as documentation while its runtime claim remains UNKNOWN.
