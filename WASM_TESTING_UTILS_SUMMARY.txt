  4. Schema validation (output conformance)
  5. Algorithm introspection (metadata registry)

Tests: 17 unit tests (all PASSING)

================================================================================
THE 5 FUNCTIONS
================================================================================

1. measure_trace_determinism(handle, activity_key, algorithm) → JSON
   ─ Purpose: Run algorithm 3 times, compare BLAKE3 hashes
   ─ Output: { algorithm, log_size, run_count, hashes, stable, all_identical }
   ─ Use case: Automated CI determinism gates

2. measure_algorithm_quality_baseline(handle, activity_key, algorithm) → JSON
   ─ Purpose: Capture fitness/precision metrics for baseline creation
   ─ Output: { algorithm, log_size, fitness, precision, quality_score, model_size }
   ─ Use case: Populate regression test baselines (5-10x faster)

3. benchmark_algorithm(handle, activity_key, algorithm, iterations) → JSON
   ─ Purpose: Measure latency percentiles (p50, p95, p99)
   ─ Output: { algorithm, iterations, p50_ms, p95_ms, p99_ms, mean_ms, min_ms, max_ms }
   ─ Use case: Performance regression detection

4. validate_output_format(output_json, algorithm) → JSON
   ─ Purpose: Check output schema conformance
   ─ Output: { algorithm, valid, missing_fields[], extra_fields[], schema_errors[] }
   ─ Use case: Catch serialization bugs (e.g., to_js() returning empty object)

5. get_algorithm_metadata(algorithm) → JSON
   ─ Purpose: Return algorithm characteristics (complexity, speed, quality, etc.)
   ─ Output: { name, display_name, category, time_complexity, space_complexity,
              speed_score, quality_score, supports_ocel, required_inputs, output_type }
   ─ Use case: CLI help generation, algorithm selection
