CRITICAL ISSUES WITH FIXES

ISSUE 1: streaming_dfg.rs HashMap Iteration
────────────────────────────────────────────
File: wasm4pm/src/streaming/streaming_dfg.rs:62
Code: pub open_traces: HashMap<String, Vec<u32>>
Risk: HashMap iteration order is random (hash randomization)
      Output edges may be in different order across runs
      BLAKE3 hash differs even though content is identical
Symptom: test_streaming_dfg_is_deterministic fails (hash mismatch)
Fix Recipe:
    // Before: iteration order random
    for (case_id, trace) in &self.open_traces { ... }
    
    // After: deterministic iteration
    let mut case_ids: Vec<_> = self.open_traces.keys().cloned().collect();
    case_ids.sort(); // Deterministic
    for case_id in case_ids {
        let trace = &self.open_traces[&case_id];
        // ...
    }
Effort: 10 minutes
Impact: HIGH — Affects all streaming algorithms

ISSUE 2: playout.rs Unseeded fastrand
──────────────────────────────────────
File: wasm4pm/src/playout.rs (multiple lines)
Code: let idx = fastrand::usize(..children.len());
      while fastrand::f64() < 0.3 { ... }
Risk: fastrand is a global unseeded RNG. Each call returns random value.
      Monte Carlo simulation is non-deterministic.
      Same trace twice produces different result.
Symptom: test_playout_unseeded_fastrand_nondeterministic fails
         (different traces each run)
Fix Recipe:
    // Before: unseeded
    pub fn playout(powl: &Powl) -> Vec<String> {
        let idx = fastrand::usize(..children.len());
        ...
    }
    
    // After: seeded
    pub fn playout(powl: &Powl, random_seed: u64) -> Vec<String> {
        let mut rng = fastrand::Rng::with_seed(random_seed);
        let idx = rng.usize(..children.len()); // Seeded
        while rng.f64() < 0.3 { ... } // Seeded
    }
Effort: 20 minutes
Impact: MEDIUM — Affects Monte Carlo simulation reproducibility

VERIFICATION STRATEGY (RANK-1 ORACLE)
================================================================================

Standard: verification.md § Testing Hierarchy § Rank-1 Oracle

Definition:
  "For all deterministic algorithms, if input is identical, output hash must
   be bit-exact identical across runs. This is a mathematical theorem, not
   a statistical property."

Implementation:
  1. Run algorithm with identical input (same log, same parameters)
  2. Compute BLAKE3(output) for each run
  3. Compare hashes
  4. Assert: all hashes MUST be identical

Failure Mode:
  If hashes differ, algorithm uses:
    • HashMap iteration (non-deterministic ordering)
    • Unseeded RNG (fastrand without seed)
    • Floating-point accumulation (order-dependent addition)
    • Thread-local state

Catch Examples:
  • HashMap leak: Run 1 edges [A→B, C→D], Run 2 edges [C→D, A→B]
    → Different order → Different hash → Oracle catches it
  • Unseeded RNG: Run 1 choice=1, Run 2 choice=2 → Different output → Caught
  • Float accumulation: Run 1 score=0.333333, Run 2 score=0.333334
    → Tiny difference but BLAKE3 different → Caught
