# Old AI vs LLMs: Why Determinism Matters

## The Core Difference

Old AI — symbolic systems built from the 1960s through the 1990s — is **deterministic**. Given the same input, a rule-based expert system, a Bayesian classifier, or a certainty-factor engine produces the exact same output every time. You can hash that output. You can chain those hashes. You can prove the computation happened.

Large Language Models are **stochastic**. Sampling temperature, random seeds, and non-deterministic GPU arithmetic mean the same prompt can yield a different answer on the next call. You cannot receipt a probability distribution.

In process manufacturing, non-determinism is not a feature — it is a defect.

## Non-Determinism Is a Defect

wasm4pm enforces **BLAKE3 receipt chains** on every cognition run. A receipt is not a log line. It is a cryptographic proof:

- `input_hash` — the exact bytes fed to the breed
- `output_hash` — the exact bytes the breed produced
- `run_id` — a stable identifier for replay

If the output changes between two runs with identical input, the receipt chain breaks. The system detects it. The line stops.

This is why the Chicago TDD doctrine reads:

> "If the code says it worked but the event log cannot prove a lawful process happened, then it did not work."
> — wasm4pm Chicago TDD doctrine

An LLM cannot satisfy that constraint. MYCIN can.

## Old AI Breeds vs LLMs

| Dimension | Old AI Breeds (wasm4pm) | LLMs (GPT-4, Claude, etc.) |
|---|---|---|
| **Determinism** | Guaranteed — same input, same output | Stochastic by design |
| **Interpretability** | Full — rules, weights, and certainty factors are inspectable | Opaque — attention weights are not an explanation |
| **Speed** | Microseconds to milliseconds | Hundreds of milliseconds to seconds |
| **Receipt-ability** | Native — BLAKE3 chain over every run | Impossible — output is sampled |
| **Auditability** | Complete — every inference step is traceable | None — no lawful inference trace |
| **Deployment size** | Kilobytes (WASM, no GPU) | Gigabytes to terabytes |
| **Failure mode** | Explicit — rules fire or they don't | Silent — confident hallucination |
| **Use case** | Manufacturing stages requiring proof | Natural language generation |

## Why MYCIN from 1976 Beats GPT-4 for Receipted Inference

MYCIN was a medical expert system built at Stanford in 1974–1976. It diagnosed bacterial infections using **certainty factors** — a numeric confidence model in the range [-1, 1] propagated through a chain of if-then rules.

When you need a **receipted diagnosis** — one where you can prove which rules fired, in which order, with which certainty factors, producing which conclusion — MYCIN's architecture is the only viable option. Its inference trace is deterministic, human-readable, and hashable.

GPT-4 can produce text that looks like a medical diagnosis. It cannot tell you which rules it applied. It cannot guarantee the same answer tomorrow. It cannot be receipted. For process manufacturing, that makes it useless at the inference layer.

wasm4pm's `mycin` breed implements certainty-factor propagation in Rust, compiled to WASM, with full receipt output. The same rules, the same certainty factors, the same input — the same receipt, every time.

## The 9 Breeds — Why Each Beats an LLM

The cognition layer exposes nine symbolic AI breeds. Each covers a class of reasoning that an LLM handles poorly — either because it requires exact reproducibility, because the domain requires a compact explainable model, or because the computation must complete in sub-millisecond time inside a WASM sandbox.

| Breed | Paradigm | Era | Why This Breed Over an LLM |
|---|---|---|---|
| `mycin` | Certainty-factor expert system | 1974–1976 | Receipted certainty propagation — LLMs cannot emit a stable certainty factor |
| `bayesian` | Bayesian inference network | 1960s–1980s | Exact posterior computation with receipted priors — LLM "confidence" is not a probability |
| `fuzzy` | Fuzzy logic controller | 1965–1980s | Continuous membership functions with deterministic defuzzification — LLMs cannot encode membership curves |
| `genetic` | Genetic algorithm optimizer | 1975 | Seeded, receipted optimization — same seed, same convergence path |
| `prolog` | Logic programming / Prolog8 | 1972 | Provable deductive reasoning — LLMs cannot guarantee logical soundness |
| `decision_tree` | Rule induction | 1979–1986 | Fully inspectable split path — LLMs are not decision trees |
| `neural_classic` | Early perceptron / MLP | 1958–1986 | Deterministic forward pass with fixed weights — not a sampler |
| `case_based` | Case-based reasoning | 1983 | Similarity retrieval from a closed case library — no hallucinated cases |
| `constraint` | Constraint satisfaction | 1970s–1990s | Exact satisfaction or proven failure — LLMs cannot guarantee constraint satisfaction |

Every breed runs inside the wasm4pm WASM kernel. Every run emits a receipt. Every receipt is verifiable by the BLAKE3 chain. None of this is possible with a language model.

## The Doctrine

> The product is CodeManufactory; RevOps is merely proof that CodeManufactory works.

Process manufacturing requires proof. Proof requires determinism. Determinism requires symbolic AI. That is why wasm4pm's cognition layer reaches back to the 1960s — not out of nostalgia, but because the receipt chain demands it.

LLMs belong at the boundary of the system: translating natural language into structured inputs that symbolic breeds can reason over, or narrating receipted outputs for human consumption. They do not belong inside the manufacturing pipeline where proof gates must pass.

The cognition layer is not a chatbot. It is a proof engine.
