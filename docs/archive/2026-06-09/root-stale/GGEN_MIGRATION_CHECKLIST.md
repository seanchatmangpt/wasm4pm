# ggen Migration Checklist

This document details the migration path for `ggen` to adopt `wasm4pm` as its external process-law oracle, using the newly extracted `ocel-core` crate.

## 1. Delete Reimplemented PM Algorithms
The following files in `ggen` must be deleted as their logic is now provided by `wasm4pm` as an external oracle:
- `crates/ggen-graph/src/ocel/dfg.rs`
- `crates/ggen-graph/src/ocel/conformance.rs`
- `crates/ggen-graph/src/ocel/projection.rs` (if generic PM analytics)
- `crates/ggen-graph/src/ocel/coverage.rs` (if generic PM analytics)
- `crates/ggen-graph/src/ocel/self_audit.rs` (if generic PM analytics)

## 2. Adopt `ocel-core` Types
`ggen`'s `crates/ggen-graph/src/ocel/ocel_types.rs` should be deleted.
All event builders in `crates/ggen-lsp/src/intel/events.rs` must repoint their imports from `ggen_graph::ocel::*` to `ocel-core::*`.
The `ocel-core` crate is extremely lightweight and only brings in `serde`, `serde_json`, and `chrono`.

### 2.1 Cross-Repo Dependency
Add the following dependency to `ggen`:
```toml
[dependencies]
ocel-core = { git = "https://github.com/seanchatmangpt/wasm4pm", tag = "ocel-core-v26.5.30" }
```

### 2.2 Serialized Name Constraint
To ensure Gall-checkpoint receipts (e.g., 001B/001C) still verify against the serialized names on disk, `ggen` must either map its existing fields to the `ocel-core` shapes (e.g. `event_type` vs `activity`) OR coordinate a rename in the proof assertions simultaneously.

## 3. Repoint Conformance and Discovery
`crates/ggen-lsp/src/intel/mine.rs` must no longer orchestrate DFG discovery or SPARQL conformance internally.
Instead, it should invoke `wpm mining conformance` as a subprocess to verify the emitted `.ggen/ocel/agent-edit-events.ocel.jsonl`.
The new NDJSON importer in `wasm4pm` seamlessly consumes the append-only stream generated by `ggen`.

## 4. Prefix Conformance / Andon Oracle
`wasm4pm` now supports `wpm prefix-conformance` (built against Petri Net incidence matrices).
`ggen` should begin polling `wpm prefix-conformance` dynamically to detect illegal state transitions ("FAKE-LIVE" or "BLOCKED") before committing resources to a full trace.
